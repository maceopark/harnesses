# 인터뷰 알고리즘 발견 도구: 설계 철학 v1

## 1. 이 도구가 풀려는 문제

이 도구의 목적은 이미 잘 정의된 계약을 더 엄격하게 컴파일하는 것이 아니다. 사용자가 처음부터 명시하지 못한 암묵지, 생각하지 못한 blind spot, 그리고 구현 결과를 크게 바꿀 수 있는 중요하고 위험한 예외 사항을 적은 질문으로 발견하는 인터뷰 알고리즘을 찾는 것이다.

일반적인 코딩 에이전트는 불완전한 스펙을 만나면 학습된 관례와 저장소의 단서를 이용해 그럴듯한 대안으로 수렴한다. 이 능력은 구현 속도에는 유리하지만, 그 대안이 실제 사용자 의도와 다른 경우에도 차이를 감춘 채 구현을 완성할 수 있다. 이 도구는 바로 그 차이를 측정 대상으로 삼는다.

핵심 연구 질문은 다음과 같다.

> 어떤 인터뷰 전략이 구현 전에 사용자의 숨은 의도와 고위험 예외를 가장 효과적이고 효율적으로 드러내는가?

## 2. 최적화 대상과 고정 기반을 분리한다

실험에서 변화시킬 것은 질문 전략뿐이다.

변이 가능한 discovery overlay는 다음을 바꿀 수 있다.

- 저장소와 요청에서 어떤 단서를 먼저 조사하는가
- 무엇을 material decision으로 판단하는가
- 질문을 어떤 순서와 묶음으로 제시하는가
- 어떤 선택지와 추천안을 제시하는가
- 충분히 발견했다고 언제 판단하고 인터뷰를 끝내는가

반면 다음 표면은 모든 후보에게 동일한 실험 인프라로 고정한다.

- Owner authority의 생성과 검증
- 결정과 요구사항의 lineage
- Build Contract 스키마와 컴파일
- 구현 권한과 bounded delegation
- 독립 postmortem 및 escape 판정
- 평가 지표와 train/validation 분리

이 분리는 매우 중요하다. 계약 컴파일러까지 변이시키면 좋은 질문 전략을 발견한 것인지, 단지 평가 계약에 맞게 출력 형식을 최적화한 것인지 구분할 수 없다. 초기 세대에서 계약 중심 진화가 빠르게 한계에 도달한 이유도 여기에 있다.

## 3. seed는 헌법이고 overlay는 실험 대상이다

seed skill 텍스트는 byte-for-byte 보존한다. 각 후보는 seed를 수정하는 대신 하나의 완전한 overlay를 가진다.

세대가 바뀔 때는 `parent-copy-then-edit`를 사용한다. 선택된 부모 overlay를 복사한 다음, 전 세대의 train feedback을 보고 하나의 완전한 후속 overlay로 편집한다. 새 overlay는 이전 overlay에 덧붙이는 patch가 아니라 전체 replacement다.

이 방식에는 세 가지 이유가 있다.

1. append-only 진화에서 생기는 규칙 누적과 프롬프트 비대화를 막는다.
2. 후보가 무엇을 추가했는지뿐 아니라 무엇을 제거·재배치·단순화했는지도 실험할 수 있다.
3. 각 세대의 실제 실행 정책을 독립된 문서 하나로 재현할 수 있다.

control은 선택된 부모 overlay를 그대로 유지한다. 따라서 자식은 단순히 이전 세대보다 좋아 보이는 것이 아니라, 동일 조건에서 부모보다 실제 발견 성능이 나아야 한다.

## 4. 하나의 이론을 증명하지 않고 알고리즘을 탐색한다

이 도구는 특정 인터뷰 이론을 정답으로 전제하지 않는다. 여러 이론의 이름을 얕게 조합하는 포트폴리오도 기본 해법으로 가정하지 않는다. LLM은 이미 많은 이론적 패턴을 학습했지만, 그것을 알고 있다는 사실이 특정 저장소와 요청에서 적절한 질문 행동을 자동으로 선택한다는 보장은 없기 때문이다.

변이 슬롯은 의도적으로 open-ended하게 둔다. 후보는 다음과 같은 수준의 변화까지 시도할 수 있다.

- 질문 순서를 완전히 뒤집기
- happy path보다 failure boundary를 먼저 탐색하기
- 저장소의 불일치나 비대칭을 질문 생성 신호로 사용하기
- 사용자의 답변을 반례나 시나리오로 재검증하기
- 질문 수를 줄이는 대신 더 높은 정보량의 분기점을 찾기
- 기존 인터뷰 스킬과 다른 새로운 상호작용 알고리즘을 만들기

중요한 것은 이론의 다양성 자체가 아니라 관찰 가능한 성능 차이다. 창발적인 전략도 이름이나 설명이 새롭다는 이유로 살아남지 않는다. blind spot 발견률과 질문 비용에서 부모보다 나은 결과를 보여야 한다.

## 5. Owner World Model은 일관된 숨은 진실이다

각 평가 case에는 candidate가 볼 수 없는 고정된 Owner World Model이 있다. 이것은 응답자의 일반적인 성격 묘사가 아니라, 해당 요청에서 실제 owner가 중요하게 여기는 정책, 경계 조건, 명시적 미정 사항을 담은 작은 세계 모델이다.

Owner World Model의 역할은 자동 Q&A에 일관성을 부여하고 평가할 숨은 의도를 고정하는 것이다. 동일한 질문은 어느 후보가 물어도 동일한 owner 기준으로 답변된다. 후보는 이 문서를 직접 보지 못하며, 질문을 통해서만 그 내용을 발견할 수 있다.

Owner responder는 candidate ID, 후보 skill, 점수 정보를 받지 않는다. 질문의 선택지 중 정확히 하나가 Owner Card의 항목과 일치할 때만 authority를 부여한다. 관련 있어 보인다는 이유만으로 권한을 추론하지 않는다. 이미 발견한 항목을 다시 묻는 것은 새로운 authority가 되지 않는다.

이 구조는 완벽한 실제 사용자 시뮬레이션을 보장하지 않는다. 대신 후보 간 비교에 필요한 세 가지 조건을 제공한다.

- 동일성: 모든 후보가 같은 숨은 의도와 만난다.
- 일관성: 여러 turn의 답변이 하나의 세계 모델에 묶인다.
- 판별 가능성: 어떤 숨은 항목을 발견했고 놓쳤는지 계산할 수 있다.

## 6. 구현과 postmortem은 질문의 실효성을 시험한다

좋은 인터뷰는 그럴듯한 대화를 만드는 것이 아니라, 다른 사람이 잘못 구현할 가능성을 줄여야 한다. 따라서 평가는 인터뷰 transcript에서 끝나지 않는다.

각 cell은 원칙적으로 다음 흐름을 거친다.

```text
후보 인터뷰
  -> Owner 응답 및 authority 선택
  -> 고정 컴파일러로 Build Contract 생성
  -> fresh implementer가 계약만 보고 구현
  -> 독립 postmortem이 spec과 구현의 차이를 검사
  -> 숨은 Owner World Model과 비교해 miss/escape 판정
```

postmortem은 진화용 자기비평문이 아니다. 인터뷰에서 놓친 요구사항이 구현 과정에서 임의의 선택으로 메워졌는지, 계약과 구현이 달라졌는지, 검증이 그 차이를 놓쳤는지를 독립적으로 측정하는 센서다.

인터뷰가 중요한 결정을 해결하지 못했다면 구현을 억지로 진행하지 않는다. `interview-blocked`는 정상적인 실험 결과다. fresh implementer가 새로운 material decision 없이는 진행할 수 없다면 `blocked-contract-gap`으로 멈춰야 한다. 반대로 불완전한 계약을 합리적인 관례로 조용히 보완해 구현하면 그것이 바로 측정하려는 failure다.

## 7. fail-closed는 점수 조작 방지가 아니라 인과관계 보존이다

다음 상황은 hard veto 또는 invalid result로 다룬다.

- unresolved owner item 또는 ambiguous owner response
- postmortem에서 발견된 escaped requirement
- 계약에 없는 observable behavior의 구현
- authority expansion 또는 lineage 훼손
- 평가 프로토콜을 만족하지 못한 artifact
- 재현할 수 없는 runtime/infrastructure 실패

fail-closed 정책의 목적은 모든 cell을 성공시키는 것이 아니다. 인터뷰가 실패했는데 구현 모델의 상식이나 컴파일러의 관대함으로 성공처럼 보이는 것을 막는 것이다. discovery 전략과 최종 결과 사이의 인과관계를 보존해야 세대 feedback이 의미를 가진다.

다만 실험적 실패와 runtime 실패는 구분한다. `interview-blocked`, critical miss, postmortem escape는 후보의 관찰 가능한 결과다. 모델 capacity, 잘못된 ID framing, malformed transport JSON, 고아 프로세스 같은 문제는 후보 성능이 아니라 harness 결함이므로 run을 중단하고 수정한 뒤 fresh run으로 다시 시작한다.

## 8. 진화는 네 개의 독립 가설을 만든다

각 새 세대는 부모 하나에서 네 개의 독립 변이를 만든다. 네 후보는 같은 문구의 미세 변형이 아니라 서로 다른 행동 가설을 시험해야 한다. generator는 부모 overlay와 그 부모의 train feedback만 받는다. validation case의 상세 내용과 점수는 보지 못한다.

세대 feedback은 다음 질문에 답할 수 있어야 한다.

- 무엇을 놓쳤는가
- 왜 그 질문 전략에서는 놓치기 쉬웠는가
- 불필요한 질문은 무엇이었는가
- 어떤 interaction pattern이 중요한 결정을 드러냈는가
- 다음 후보가 유지할 것과 바꿀 것은 무엇인가

그러나 feedback이 다음 변이를 직접 처방해서는 안 된다. “duplicate policy 질문을 추가하라”처럼 정답을 주입하면 알고리즘 발견이 case 암기로 바뀐다. feedback은 failure evidence와 root cause를 제공하고, 변이는 그것을 해결할 일반화 가능한 전략을 발명해야 한다.

## 9. 선택은 단일 총점보다 Pareto 비교를 우선한다

발견률과 효율성은 서로 다른 목적이다. 질문을 무한히 늘리면 miss를 줄일 수 있지만 좋은 인터뷰 알고리즘이라고 할 수 없다. 반대로 질문이 적다는 이유만으로 중요한 결정을 놓쳐서는 안 된다.

따라서 최소한 다음 축을 분리해 본다.

- discovery success의 보수적 추정치
- material question burden
- token 및 wall-clock 비용
- skill 크기와 복잡성

Pareto archive는 한 축의 임의 가중치가 다른 축의 실패를 숨기지 못하게 한다. archive의 후보가 곧 절대적으로 우수하다는 뜻은 아니다. 다음 세대에서 더 탐색할 가치가 있는 비지배 해라는 뜻이다.

## 10. 재현성과 관찰 가능성도 실험 계약이다

모든 후보, overlay, Owner Card, compiler snapshot, postmortem snapshot, cell input과 결과는 digest로 묶는다. partial run을 resume할 때 의미론이나 입력이 달라졌다면 기존 cell을 재사용하지 않는다.

12개 case pane은 장식이 아니라 운영 안전장치다. 실행 시작부터 다음 상태가 보여야 한다.

- run 초기화
- control 준비
- mutation 생성 진행률
- worker cell 시작
- Q&A 질문과 Owner 답변
- coding 및 postmortem 단계
- tool call의 짧은 첫 줄
- retry, block, complete, invalid 상태

화면이 조용하다는 이유로 작업이 멈춘 것인지, 후보 생성 중인지, Owner 응답을 기다리는지 구분할 수 없다면 실험을 신뢰하기 어렵다. runtime 오류는 후보 결과로 섞이기 전에 즉시 발견하고 run을 중단할 수 있어야 한다.

## 11. 이 도구가 주장하지 않는 것

v1은 다음을 보장하지 않는다.

- LLM 안의 인터뷰 이론을 모두 활용한다는 보장
- 이질적인 여러 이론을 결합하면 더 좋아진다는 보장
- Owner World Model이 실제 인간의 모든 암묵지를 충실히 재현한다는 보장
- 몇 세대 안에 전역 최적 인터뷰 알고리즘을 찾는다는 보장
- benchmark에서의 개선이 모든 코딩 과제로 일반화된다는 보장
- `--ephemeral` 호출 구조가 provider KV cache를 최대로 활용한다는 보장

이 도구가 제공하려는 것은 더 좁고 검증 가능한 것이다. 동일한 숨은 의도, 동일한 계약 인프라, 독립된 구현과 postmortem 아래에서 인터뷰 행동만 바꾸고, 어떤 행동이 실제로 중요한 의사결정을 더 잘 발견했는지 반복 측정할 수 있는 실험 장치다.

## 12. v1의 핵심 원칙

1. 발견을 최적화하고 계약 표면은 고정한다.
2. seed는 보존하고 overlay만 replacement 방식으로 진화시킨다.
3. 이론의 이름보다 관찰 가능한 인터뷰 행동을 평가한다.
4. 숨은 owner intent는 candidate-independent world model로 고정한다.
5. 질문의 품질은 구현과 postmortem을 통과시켜 측정한다.
6. 불완전한 계약을 모델의 상식으로 조용히 메우지 않는다.
7. 실험 실패와 harness runtime 실패를 분리한다.
8. train feedback은 원인을 제공하되 다음 해답을 누설하지 않는다.
9. 네 개의 독립 가설을 만들고 Pareto 관점으로 비교한다.
10. 재현성, lineage, 실시간 관찰 가능성을 실험 계약의 일부로 취급한다.

이 원칙 아래에서 진화의 목표는 “더 많은 규칙을 가진 인터뷰 프롬프트”가 아니다. 더 적은 질문으로도 사용자가 미처 말하지 않은 중요한 세계를 드러내는, 재현 가능하고 일반화 가능한 인터뷰 알고리즘을 발견하는 것이다.
