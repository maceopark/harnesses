# Ultimateinterview Lessons

Signal-to-lens routing rules learned from spec postmortems. The `ultimateinterview` skill reads this file during Orientation: when a signal below appears in a new request or the touched code, treat the named lens as triggered. Keep signals observable at interview time, never hindsight. `Fired/Caught` is fire-tracking: postmortems increment Fired when the signal appeared, Caught when the triggered lens actually produced a ledger entry; Fired ≥ 3 with Caught 0 retires the row.

| Signal | Lens to trigger | Failure class | Evidence | Date | Fired/Caught |
| --- | --- | --- | --- | --- | --- |
| User-supplied text crosses an input-to-persistence or output byte boundary, while the spec defines semantic validation (for example emptiness, length, or control characters) but not encoding/normalization failure policy - decide whether unencodable or non-canonical values are rejected at input, load, or render time | domain/state | enumeration-miss | todo-cli-app-4 postmortem: `_validate_title` rejects control chars on `add` only; `storage._task_from_validated_data` accepts any str title on load, so a hand-edited newline title breaks the `<id>\t[ ]\t<title>` list contract; todo-cli-benchmark-new postmortem: REQ-004 named Cc only, so a lone surrogate required requester resolution after it could crash UTF-8 output/persistence | 2026-07-11 | 2/1 |
| Spec names a file-store path or an env/flag store-path override seam - enumerate the store-ACCESS error surface beyond "corrupt JSON": missing parent directory, permission-denied / unreadable, non-UTF-8 / undecodable bytes, AND the override seam's own edge values (empty string, relative path, unexpanded ~) - each needs a defined exit class | domain/state | enumeration-miss | todo-cli-app-4 postmortem: storage.load raises StorageError (exit 3) for permission/OSError and decode errors, save fails if parent dir absent, and empty TODO_FILE silently falls back to ~/.todos.json - all substantive and none in the handoff (g13 covered only invalid-JSON + schema-invalid; the seam was named but its edges were not) | 2026-07-06 | 2/1 |
| Spec pins a closed on-disk schema for a store the tool owns AND declares migration a non-goal - decide the unknown/extra-field policy explicitly (reject vs ignore-and-preserve); strict exact-key rejection turns every future schema addition into a breaking change for existing stores | domain/state | enumeration-miss | todo-cli-app-4 postmortem: `_store_from_validated_data`/`_task_from_validated_data` reject any extra or missing key (`set(data) != {...}`), so a store with one added field fails exit 3; forward-compat consequence never enumerated despite migration being a non-goal | 2026-07-06 | 2/1 |

These three store rules were briefly over-promoted to an unconditional audit gate (2026-07-07) and returned to staging: at 1/1 the evidence is one closed loop, not enough to become blanket methodology. The audit-checklists store-trust gate is now conditional (durable/hand-editable stores only); these rows keep eliciting the questions at Orientation and accumulate fire evidence until promotion is earned.
