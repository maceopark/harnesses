# 증거 권한 보존형 모델 갱신

## 상태와 결론

이 문서는 `ultimateinterview`의 unknown-unknown 발견 방식을 검토하며
도출한 **설계 메모**다. 구현 사양이나 효과 입증이 아니다.

처음의 확장안은 S0 분류, claim 상태, 반사실 probe 카드, 카드 수 제한,
closure 재검증, holdout 평가를 한 계약에 모아 두었다. 그 계약은 안전한
교정안이지만, 그대로는 독립적인 통제들을 기계적으로 결합한 형태에
가깝다. 이 문서의 목적은 그 안에서 실제로 하나의 인과 구조를 이루는
최소 방법만 남기는 것이다.

핵심 명제는 다음과 같다.

> 새 요구사항은 기존 증거가 무엇을 결정할 수 있는지, 즉 그 증거의
> 적용 범위와 권한을 바꿀 수 있다. 그러므로 계획을 확장하기 전에
> 변화의 종류를 판정하고, 필요한 경우에만 판별 가능한 대안을 세운 뒤,
> 그 결과를 기존의 권한 경로로 되돌려야 한다.

이 명제는 기존 evidence-first 라우팅을 대체하지 않는다. 오히려 새
요구사항 때문에 과거의 `CLEAR` 또는 기존 근거가 과도하게 일반화되는
것을 막는 보완이다.

## 최소 제어 루프

```text
새 요구사항 Δ
  -> Δ가 기존 모델 안의 우선순위 이동인지, 모델의 확장인지,
     기존 제약의 무효화인지 판정
  -> 기존 증거가 계속 유효한 좌표와 더 이상 적용되지 않는 좌표를 분리
  -> 아직 구분되지 않는 중요 사실에만 대안 가설 하나를 생성
  -> 읽기 전용 조사 또는 검증으로 두 설명을 판별
  -> 기존 controller가 사실, 가역적 기본값, 오너 결정, 잔여 리스크로 귀속
```

이 순서가 방법의 유기적 연결부다. 각 단계는 앞 단계의 출력을
소비한다.

- 변화 판정 없이 대안을 만들면, 이미 오너가 알고 있는 우선순위 변경을
  숨은 사실처럼 조사하게 된다.
- 현재 증거의 범위를 기록하지 않으면, 과거 사실을 새 consumer, 시간,
  환경, 권한에 근거 없이 적용하게 된다.
- 대안과 판별 없이 pattern prior를 쓰면, LLM의 학습된 패턴이 근거나
  기본값처럼 승격된다.
- 기존 controller로 되돌리지 않으면, probe가 정책 결정을 내리거나
  사실을 과장해 closure를 선언하게 된다.

따라서 이 방법은 lens, 질문, 점수, 별도 ledger를 하나 더 추가하는
방법이 아니다. **기존 evidence/authority 라우팅 앞에 범위 갱신을 두고,
필요한 경우에만 하나의 판별 루프를 삽입하는 방법**이다.

## 1. 변화 판정: 기존 모델에 대한 Δ의 의미

모든 새 요구사항은 먼저 다음 셋 중 하나로 분류한다. 이 분류 자체가
답을 내리지는 않는다. 단지 기존 근거와 결정의 재사용 가능 범위를
정한다.

| 변화 종류 | 의미 | 먼저 해야 할 일 |
| --- | --- | --- |
| 같은 모델 안의 목표/우선순위 이동 | 해결 공간은 같고 무엇을 더 중요하게 볼지만 달라졌다. | 오너가 우선순위와 acceptance를 다시 정한다. 별도 사실 리스크가 없으면 probe를 만들지 않는다. |
| 모델의 확장 | 새 interface, consumer, 권한, 시간, 환경, 데이터 표현 같은 좌표가 추가되었다. | 기존 증거의 유효 범위를 기존 좌표로 제한하고 새 좌표의 근거를 별도로 찾는다. |
| 제약 또는 모델의 무효화 | 법적, 보안, 데이터 모델, 의미론적 제약이 이전 선택을 더 이상 가능하게 하지 않는다. | 의존하는 기본값·결정·acceptance를 다시 열고, 실행 가능한 공간을 재도출한다. |

중요한 구분은 “이전 근거가 틀렸는가”와 “이전 근거가 새 좌표를
보장하지 않는가”다. 확장은 전자를 뜻하지 않는다. 반대로 무효화는
단순한 미확정 상태가 아니라, 의존하던 결론을 더 이상 사용하면 안 되는
상태다.

## 2. 조건부 반사실 판별

반사실 가설은 모든 요구사항이나 모든 boundary에 적용하지 않는다.
다음 조건이 동시에 만족될 때만 사용한다.

1. 변화 판정 후에도 구현이나 acceptance를 바꿀 수 있는 중요한 사실이
   남아 있다.
2. 현재의 로컬 증거만으로 두 설명을 구분할 수 없다.
3. 각 설명을 갈라놓을 제한된 조사, 테스트, trace, schema 확인, 또는
   오너 결정 경로가 있다.

그때의 최소 기록은 다음 네 항목이면 충분하다.

| 항목 | 의미 |
| --- | --- |
| 현재 근거와 적용 범위 | 무엇을 보았고, 어느 consumer·시간·환경까지 말할 수 있는가 |
| 대안 | 현재 설명과 다른, 구현 또는 acceptance를 바꾸는 설명 하나 |
| 판별자 | 두 설명에서 결과가 달라지는 가장 작은 조사 또는 검증 |
| 귀속 | 결과를 증거, 가역적 기본값, 오너 결정, 명시적 잔여 리스크 중 어디로 보낼지 |

LLM이 제안한 pattern은 두 번째 행의 후보일 뿐이다. 로컬 anchor와
판별자가 없으면 계획, 기본값, 안전성, 발견 성과의 근거가 될 수 없다.

## 3. 권한 라우팅은 하나만 둔다

판별 결과는 새 상태 기계나 별도 discovery 권한으로 가지 않는다. 기존의
권한 경로 하나로 귀속한다.

| 결과 | 귀속 |
| --- | --- |
| 코드, 데이터, 운영 관찰이 한 설명을 지지 | 증거로 기록하고 해당 범위에서만 사실로 사용 |
| 남은 선택이 가역적이고 오너의 정책 결정을 요구하지 않음 | 근거와 검토 시점이 있는 가역적 기본값 |
| 남은 선택이 정책, trade-off, 비가역 변경임 | 적합한 오너에게 결정 요청 |
| 지금은 확인하거나 결정할 수 없음 | owner, 기한, 결과를 적은 명시적 잔여 리스크 |

따라서 `CLEAR`는 “그 주장에 적절한 귀속이 있다”는 라우팅 결과일 뿐이다.
구현 완료, 전 범위 안전, 또는 다른 좌표까지의 coverage를 뜻하지 않는다.

## 방법론에 남기지 않을 것

다음은 유용할 수 있지만 핵심 방법 그 자체가 아니다.

| 항목 | 둘 위치 |
| --- | --- |
| 한 planning wave에서 실행할 probe 수 | 실험 또는 운영 설정 |
| 상세 상태 어휘와 closure 템플릿 | 현재 ledger/schema가 실제로 필요로 할 때의 구현 설계 |
| preregistration, blind hidden holdout, 비교 arm | 효과를 검증하는 연구 프로토콜 |
| 일반적인 boundary 점검, 반복 sweep, contrarian 횟수 | 현행 risk routing의 후보 입력; coverage 증명으로 사용하지 않음 |

이 분리는 “보호 장치가 많을수록 방법이 좋아진다”는 착각을 막는다. 핵심
루프에 인과적으로 필요하지 않은 제약은 실험 설계나 운영 규칙으로
내려야 한다.

## 최소성 검증: 채택 전 ablation

이 제안은 아직 효능이 검증되지 않았다. 따라서 스킬에 넣기 전에는
구성요소를 추가로 쌓기보다 다음 반증을 먼저 한다.

| 제거한 요소 | 실제로 잃어야 하는 보호 효과 | 잃지 않는다면 |
| --- | --- | --- |
| 변화 판정 | 확장과 무효화가 과거 증거의 범위를 넘어서 재사용되는 것을 막는 능력 | 변화 판정을 제거 |
| 대안 가설 | 중요한 미확정 사실에 대해 기존 설명을 반증할 기회 | 대안 생성을 제거 |
| 판별자 | pattern prior가 사실이나 기본값으로 승격되는 것을 막는 능력 | 가설 기록을 제거 |
| 동일 권한 라우팅 | probe가 정책/closure 권한을 빼앗지 않는 보호 | 별도 probe 상태를 제거 |

각 행에서 실제 손실이 관찰되지 않으면 그 요소는 방법론이 아니라
의례다. 특히 과거 escape에 사후적으로 잘 맞는다는 사실만으로는
채택 근거가 되지 않는다.

## 평가 원칙

효과를 검증하려면 이 방법과 평가 프로토콜을 분리한다.

1. baseline evidence/authority controller와, 그 controller에 이 최소
   판별 루프를 더한 arm을 비교한다.
2. 개발용 사례와 독립적으로 작성한 숨은 holdout을 분리한다.
3. 발견 성과는 구현 전에 기록된 후보가 독립적인 escape와 일대일로
   이어진 경우에만 준다.
4. 추가 질문, unsupported default, authority error, 더 큰 도구/시간
   예산은 이득과 별도로 비용과 실패로 기록한다.

통과해도 그것은 더 큰 연구를 할 근거일 뿐, 범용성이나 완전성을 증명하지
않는다.

## 비채택 조건

다음 중 하나가 발생하면 이 제안은 채택하지 않거나 중단한다.

- 모든 boundary 또는 모든 입력의 보완집합을 열거하도록 변질된다.
- 정상 evidence routing으로 확인 가능한 사실을 사용자 질문으로 바꾼다.
- 한 probe가 여러 독립 발견의 공로를 주장하거나, policy 결정을 숨은
  사실로 바꾼다.
- 판별자가 없는 LLM pattern을 기본값 또는 acceptance 근거로 사용한다.
- 기존 ledger/Build Contract에 실제 contract delta를 만들지 못한 채
  문서만 늘린다.
- holdout에서 추가 질문, unsupported default, authority error, 또는
  예산 증가를 대가로만 발견을 늘린다.

## 현재 결정

현재 이 제안은 **유기적인 핵심으로 압축 가능한 설계 가설**이다.
아직 `ultimateinterview`의 새 기본 절차나 범용 unknown-unknown 발견
기법으로 채택하지 않는다. 다음 구현 또는 스킬 변경은 위의 최소성
검증과 독립 holdout이 실제로 이득을 보인 뒤에만 검토한다.
