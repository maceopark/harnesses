Ultimateinterview · current architecture

We built an interview monster.
Then taught it when to stop.

A story about absorbing the best ideas from interview skills, turning every safety dial to eleven, and discovering that the missing feature was not another question. It was a receipt for every improvisation.

The original problem

One reasonable request can produce two reasonable—and incompatible—implementations.

“Retry failed order creation.”

Implementation A

Retries every timeout. Fast, familiar, and capable of charging twice after a lost response.

Implementation B

Never retries. Avoids duplication, but may abandon an order the vendor already committed.

The coding model is not confused. The product decision was never made.

Experience before invention

I studied interview skills deeply—and kept their best moves.

grilling / grill-meOne dependent question at a time; relentlessly walk the decision tree.
grill-with-docsMake hard decisions and domain language durable through ADRs and a glossary.
Prometheus / ulw-planExplore before asking; produce a decision-complete plan for an executor with no interview context.
Native Claude and Codex plannersAdapt intelligently to the repository and use the execution environment’s own strengths.

Basis: personal use and structural analysis—not a controlled comparison. Ultimateinterview absorbs these strengths; its distinct addition appears on slide 8.

Dramatic reenactment · counts are real

The model did exactly what we asked: never stop finding risk.

Request

“Build a simple Todo CLI.”

Round 1: the three reviewers challenge the missing cases.
Round 4: the reviewers challenge the fixes to the missing cases.
Round 7: the reviewers review the comments about the reviewers’ previous comments.

The Todo CLI needed a few commands. The interview had a constitution.

The real diagnosis

The problem was not weak reasoning. It was unbounded obedience.

What we rewarded

Find another edge case. Ask another clarifying question. Add another reviewer. Never risk stopping early.

What the user needed

Resolve only decisions that can materially change the implementation, then hand off a small, testable contract.

When intelligence is cheap, the scarce resource is permission to stop.

Simplification, not retreat

We did not make the model less capable. We narrowed what deserves ceremony.

Keep repository grounding

Inspect the nearest two or three governing surfaces.

Keep material owner decisions

Ask only when different answers change behavior, authority, boundaries, failure, or verification.

Keep deterministic lineage

Decision → authority → requirement → acceptance → verification.

Keep one fresh handoff check

One outsider, at most three admissible blockers—not a review parliament.

The missing control plane

The model can quietly become the product owner twice.

Before coding

A decision disappears or weakens while conversation becomes a handoff.

Control: compile authority and exact decision lineage into a sealed Build Contract.

During coding

The implementer meets an internal gap and makes a reasonable choice nobody can later see.

Control: bounded discretion plus a digest-bound decision.jsonl receipt before acting.

The compiler blocks unauthorized meaning. The receipt makes authorized discretion auditable.

Material decision loop

Could two compliant implementations differ materially?

Yes→Resolve only that authority or decision
No→Stop interviewing
Authority unavailable→Finish incomplete—never guess

Three material owner decisions are a soft reassessment point, not a quota. Clear requests take the fast path with zero questions.

A small execution contract

The source of truth is short enough to read—and strict enough to compile.

Outcome & Boundaries

Goal, in-scope surfaces, and non-goals.

Decisions & Defaults

Atomic DEC-NNN rows, each with one authority.

Acceptance

Input → action → observable success → applicable failure.

Verification

Context-complete commands or scenarios tied to acceptance.

No separate ambiguity ledger, question score, transcript snapshot, or duplicated human-authored authority register.

The authority boundary

The repository can tell us what exists. It cannot decide what the product should become.

Evidence only

Current behavior, tests, docs, conventions, model recommendations, reviewer consensus, and owner silence.

Normative authority

Explicit owner decision

Applicable canonical contract

Bounded delegation

Consensus can discover a gap. It cannot authorize the answer.

Why contract compilation exists

A fluent summary can lose one phrase—and change the product.

Without the compiler

Owner: “Hide completed todos by default.”

Handoff: “Support listing todos.”

Executor: lists everything.

Test: command exits 0. Pass.

With the compiler

DEC-003 keeps the exact decision.

One authority maps to one REQ.

Acceptance observes completed items being absent.

Verification asserts the actual output.

If any link disappears, weakens, shares a requirement, or invents authority, the projection gate refuses to produce the sealed build-contract.json.

How to use decision.jsonl

The receipt turns “the model probably chose this” into evidence we can inspect.

Without it, we either ask the owner about every helper and revive the interview monster—or let the implementer decide silently.

The permitted choice is logged before acting: gap, decision, rationale, alternatives, affected paths, observable impact, and contract digest.

Target code reviewStart with every logged affected_path.
Challenge claimed impactCompare observable_impact with actual CLI behavior and tests.
Find unexplained behaviorA substantive diff with no requirement, delegation, or receipt is suspicious.
Create regressionsTurn repeated escapes into tests and future discovery signals.

The receipt is evidence, never authority. Product-visible or out-of-delegation choices must stop and return to the owner.

The payoff

This is not documentation theater. It is a detector for where intent changed.

Now we can distinguish authorized variation from an escaped requirement, handoff loss, or implementation drift—and fix the earliest mechanism that failed.

What is genuinely new here

I did not invent better questions.
I made discretion inspectable.

Other skills taught the model how to investigate. Ultimateinterview adds a narrow authority boundary, a deterministic stop rule, and a receipt trail that lets us detect when implementation quietly became product design.

That is why the simpler version is stronger: it spends intelligence on material uncertainty—and preserves evidence whenever the model must improvise.

Takeaway

The best interviewer knows
when to shut up—
and keeps receipts.

Use Ultimateinterview

Cross-session handoffs, money, data, permissions, compatibility, failure semantics, irreversible change, or any task where silent product decisions are expensive.

Use a lighter planner

Typos, reversible refactors, mechanical updates, or work already pinned by an authoritative contract.
