Ultimateinterview · 현재 아키텍처

인터뷰 괴물을 만들었다.
그리고 멈추는 법을 가르쳤다.

여러 인터뷰 스킬의 장점을 흡수하고, 모든 안전장치를 끝까지 올린 뒤, 마지막으로 부족했던 것은 새 질문이 아니라 즉흥 결정마다 남기는 영수증이라는 사실을 깨달은 이야기.

출발점

합리적인 요구 하나가 합리적이지만 서로 양립할 수 없는 구현 둘을 만든다.

“주문 생성이 실패하면 재시도해 주세요.”

구현 A

모든 타임아웃을 재시도한다. 빠르고 익숙하지만, 응답만 유실됐을 때 이중 결제가 가능하다.

구현 B

절대 재시도하지 않는다. 중복은 막지만, 공급자가 이미 커밋한 주문을 버릴 수 있다.

코딩 모델이 헷갈린 게 아니다. 제품 결정이 내려지지 않았다.

발명보다 먼저 한 일

여러 인터뷰 스킬을 깊게 써 보고 구조를 분석해, 가장 강한 동작을 남겼다.

grilling / grill-me의존 순서대로 한 번에 한 질문씩, decision tree를 끈질기게 내려간다.
grill-with-docs어려운 결정과 도메인 언어를 ADR과 glossary로 오래 남긴다.
Prometheus / ulw-plan묻기 전에 조사하고, 인터뷰 맥락이 없는 executor를 위한 decision-complete plan을 만든다.
Claude·Codex 네이티브 planner저장소에 지능적으로 적응하고 실행 환경 자체의 강점을 활용한다.

근거: 개인적인 사용 경험과 구조 분석. 통제된 비교 실험은 없으며, 고유한 추가점은 8번 슬라이드에서 설명한다.

사건 보고서 · 숫자는 실제다

작은 Todo CLI 하나.
리뷰어 3명. 7라운드.

90분

구현을 시작하기 전 인터뷰에 사용한 시간.

3자 독립 리뷰각 리뷰어가 서로 다른 누락 유형을 찾았다.
완전한 리뷰 7라운드수정할 때마다 새 예외, 렌즈, readiness 질문이 열렸다.
총 21회 리뷰 통과Todo CLI는 계속 작았다. 보증 절차가 더 큰 시스템이 됐다.

극적 재연 · 숫자는 실제다

모델은 우리가 시킨 일을 정확히 했다. 위험 찾기를 멈추지 않았다.

요청

“간단한 Todo CLI를 만들어 주세요.”

1라운드: 리뷰어 3명이 빠진 예외를 지적한다.
4라운드: 리뷰어들이 그 예외를 고친 방식의 예외를 지적한다.
7라운드: 리뷰어들이 이전 리뷰 코멘트에 대한 리뷰 코멘트를 리뷰한다.

Todo CLI에는 명령 몇 개가 필요했다. 인터뷰에는 헌법이 생겼다.

진짜 진단

문제는 추론 능력 부족이 아니라 끝없는 성실함이었다.

우리가 보상한 것

예외를 하나 더 찾아라. 질문을 하나 더 하라. 리뷰어를 하나 더 붙여라. 너무 일찍 멈추지 마라.

사용자가 필요했던 것

구현을 실질적으로 바꾸는 결정만 해결하고, 작고 검증 가능한 계약을 넘겨라.

지능이 싸진 시대의 희소 자원은 멈춰도 된다는 허가다.

후퇴가 아니라 증류

모델의 능력을 낮춘 게 아니다. 의식이 필요한 범위를 좁혔다.

저장소 grounding은 유지

가장 가까운 지배 표면 두세 곳만 먼저 본다.

중요한 owner decision은 유지

답에 따라 동작, 권한, 경계, 실패, 검증이 바뀔 때만 묻는다.

결정론적 lineage는 유지

결정 → 권한 → 요구사항 → 인수조건 → 검증.

fresh handoff check는 한 번만

외부 시선 하나, 허용 blocker 최대 세 개. 리뷰 의회는 만들지 않는다.

빠져 있던 통제면

모델은 두 번 조용히 product owner가 될 수 있다.

코딩 전

대화가 handoff로 요약되면서 확정한 결정이 사라지거나 약해진다.

통제: 권한과 정확한 결정 lineage를 sealed Build Contract로 컴파일한다.

코딩 중

구현자가 내부 gap을 만나 합리적인 선택을 하지만 나중에는 아무도 그 선택을 볼 수 없다.

통제: bounded discretion과 행동 전 digest-bound decision.jsonl 영수증.

컴파일러는 권한 없는 의미를 막고, 영수증은 허용된 재량을 감사 가능하게 만든다.

중요 결정 루프

두 개의 준수 구현이 실질적으로 다른 결과를 낼 수 있는가?

예→그 권한 또는 결정만 해결
아니오→인터뷰 종료
권한 없음→추측하지 말고 incomplete

중요 owner decision 세 개는 soft 재평가 지점이지 할당량이 아니다. 명확한 요청은 질문 0개의 fast path로 간다.

작은 실행 계약

사람이 읽을 만큼 짧고, 컴파일할 만큼 엄격한 source of truth.

Outcome & Boundaries

목표, 범위, non-goal.

Decisions & Defaults

각각 하나의 권한을 가진 원자적 DEC-NNN.

Acceptance

입력 → 행동 → 관찰 가능한 성공 → 적용 가능한 실패.

Verification

인수조건에 연결된 맥락 완전한 명령 또는 시나리오.

별도 ambiguity ledger, 질문 점수, transcript snapshot, 사람이 중복 작성한 authority register는 없다.

권한 경계

저장소는 현재 무엇이 있는지 말해 준다. 제품이 무엇이 되어야 하는지는 결정하지 못한다.

증거일 뿐

현재 동작, 테스트, 문서, 관례, 모델 추천, reviewer consensus, owner의 침묵.

규범적 권한

명시적 owner decision

적용 가능한 canonical contract

bounded delegation

합의는 gap을 발견할 수 있다. 답을 승인할 수는 없다.

계약 컴파일이 필요한 이유

유창한 요약이 문구 하나를 잃고 제품을 바꿀 수 있다.

컴파일러가 없으면

Owner: “완료 항목은 기본 목록에서 숨긴다.”

Handoff: “Todo 목록을 지원한다.”

Executor: 모든 항목을 표시한다.

Test: 명령이 0으로 끝난다. 통과.

컴파일러가 있으면

DEC-003이 결정 문구를 그대로 보존한다.

하나의 권한이 하나의 REQ에 연결된다.

인수조건은 완료 항목이 없음을 관찰한다.

검증은 실제 출력을 assert한다.

연결이 사라지거나 약해지거나, 요구사항을 공유하거나, 권한을 발명하면 projection gate는 sealed build-contract.json 생성을 거부한다.

decision.jsonl을 써먹는 법

“모델이 아마 이렇게 정했겠지”를 검사 가능한 증거로 바꾼다.

기록이 없으면 helper 이름까지 owner에게 물어 인터뷰 괴물을 부활시키거나, 구현자가 조용히 결정하게 된다.

허용된 선택은 행동 전에 gap, 결정, 이유, 대안, 영향 경로, 관찰 영향, 계약 digest를 남긴다.

코드리뷰 표적화기록된 모든 affected_path부터 본다.
영향 주장 검증observable_impact와 실제 CLI 동작·테스트를 비교한다.
설명 없는 동작 발견요구사항·위임·영수증이 없는 substantive diff는 의심 대상이다.
회귀 방지반복되는 escape를 테스트와 다음 discovery 신호로 바꾼다.

영수증은 증거이지 권한이 아니다. 제품에 보이거나 위임 밖인 선택은 멈추고 owner에게 반환해야 한다.

실제 효용

문서를 위한 문서가 아니다. 의도가 어디서 바뀌었는지 찾는 detector다.

Sealed contract
기대한 동작→Compiled plan + 영수증
허용된 선택→Diff + tests
실제 동작→Postmortem
gap 분류

Contract → implementation

모든 요구사항이 구현되고 직접 검증됐는가?

Implementation → contract

모든 substantive behavior에 요구사항, bounded delegation 또는 유효한 영수증이 있는가?

이제 authorized variation, escaped requirement, handoff loss, implementation drift를 구분하고 가장 먼저 실패한 메커니즘을 고칠 수 있다.

정직한 비교

이 주장은 실행하지 않은 벤치마크가 아니라 경험과 구조 분석에서 나온다.

능력강한 인터뷰 스킬Ultimateinterview
좋은 질문대체로 매우 강함장점을 흡수
저장소 우선 조사좋은 워크플로에 흔함brownfield에서 필수
예외사항 압박주요 강점중요할 때만 사용
멈출 시점판단 또는 prompt 관례인 경우가 많음명시적 반사실 종료 테스트
임의 구현 선택 노출맥락이나 산문에 남기 쉬움행동 전 digest-bound 결정 영수증
handoff 뒤 의도 drift 탐지같은 맥락에 의존하기 쉬움독립적인 양방향 contract audit

정말 새로 추가한 것

더 좋은 질문을 발명한 것이 아니다.
재량을 검사 가능하게 만들었다.

다른 스킬들은 모델에게 조사하는 법을 가르쳤다. Ultimateinterview는 좁은 권한 경계, 결정론적 종료 규칙, 그리고 구현이 조용히 제품 설계로 변한 순간을 탐지하는 영수증 trail을 더했다.

그래서 단순한 버전이 더 강하다. 지능은 중요한 불확실성에만 쓰고, 모델이 즉흥적으로 선택할 때는 증거를 남긴다.

결론

최고의 인터뷰어는
입을 다물 때를 알고—
영수증을 남긴다.

Ultimateinterview를 쓸 때

세션 간 handoff, 돈, 데이터, 권한, 호환성, 실패 의미론, 비가역 변경처럼 조용한 제품 결정이 비싼 작업.

가벼운 planner를 쓸 때

오타, 가역적 refactor, 기계적 업데이트, 이미 권위 있는 계약으로 고정된 작업.
